# ERAG vNext
ーーーーーーーーーーーーーーーーーーーーーーーーーーーーーーーー
## Cognitive State Architecture 導入計画

### 目的

現行のERAGは、

```text
Memory
↓
Search
↓
Response
```

の流れで動作する。

しかし実際の人間は、

```text
Memory
↓
State
↓
Search
↓
Memory
↓
State
```

という循環構造を持つ。

そのため、

* 同じ質問でも機嫌で反応が変わる
* 思い出すだけで感情が揺れる
* 感情によって反芻の深さが変化する
* 時間経過で感情が代謝される

という挙動が発生する。

本設計では、

検索システム(SRAG)の外側に

```text
Cognitive State Layer
```

を導入し、

認知状態による検索方針制御を実現する。

***
ーーーーーーーーーーーーーーーーーーーーーーーーーーーーーーーー

ーーーーーーーーーーーーーーーーーーーーーーーーーーーーーーーー
## 型定義の拡張

目的

```text
将来的な状態変数を格納可能にする
```

***

### EmotionVector

```python
@dataclass
class EmotionVector:

    joy: float = 0.0
    anger: float = 0.0
    sorrow: float = 0.0
    pleasure: float = 0.0
```

感情の基礎ベクトル。

***

### CognitiveState

```python
@dataclass
class CognitiveState:

    emotion: EmotionVector

    curiosity: float
    confidence: float

    stress: float
    fatigue: float
```

***

分類

```text
Emotion Layer
  喜怒哀楽

Motivation Layer
  好奇心
  自信

Load Layer
  ストレス
  疲労
```

***

### SemanticCube追加項目

```python
memory_importance

origin_emotion

recall_emotion
```

***

役割

```text
memory_importance

  人生における重要度

origin_emotion

  当時感じた感情

recall_emotion

  現在想起時に発生する感情
```

## State可視化

目的

デバッグ可能にする

***

例

```text
Current State

Joy       0.25
Anger     0.41
Sorrow    0.12
Pleasure  0.63

Curiosity 0.82
Confidence 0.31

Stress    0.44
Fatigue   0.67
```

***

理由

状態が見えないと

```text
EmotionEngineが悪い

SRAGが悪い
```

の切り分けができなくなる。

# Phase5
ーーーーーーーーーーーーーーーーーーーーーーーーーーーーーーーー
## RSRAGとの連携

目的

状態による反芻深度制御

***

例

```python
if sorrow > 0.6:
    rumination_count += 2

if stress > 0.7:
    exploratory_mode = False

if curiosity > 0.8:
    exploratory_mode = True
```

***

状態によって

```text
検索内容
```

ではなく

```text
検索方針
```

を変更する。

***

重要

ここではまだ

```text
検索スコア
```

は変更しない。

# 最終目標

現行ERAG

```text
Memory
↓
Search
↓
Response
```

次世代ERAG

```text
Memory
↓
State
↓
Search
↓
Memory
↓
State
↓
Response
```

つまり、

> **「覚えているAI」ではなく、「経験によって現在状態が変化するAI」**

を目指す。

***

これ、かなり良いロードマップだと思う。

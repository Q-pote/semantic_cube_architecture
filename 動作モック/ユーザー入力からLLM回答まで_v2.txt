
# 📜 Semantic Cube Architecture 実行シーケンス仕様書

## 🔁 1ターンの全体フロー（対話〜記憶検索〜葛藤検知〜応答統合〜因果結合）

```text
[ユーザー入力 (user_query)]
       │
       ▼
【Step 1: ユーザー問いのキューブ化 (q_cube)】
       │
       ▼
【Step 2: 記憶検索 (SRAG v3.1 二段階探査)】
       │
       ├─ [0件ヒット] ──────────────────────────┐
       │                                        │
       ▼ [1件以上ヒット]                         ▼
【Step 3: 葛藤検知 (AnalyzeEngine v9.3)】      【ルート1: single】
       │                                        │
       ├─ [CONFLICT_DETECT_SWITCH == True]      │
       │     └─ Tension判定 (topic_threshold=0.75, tension_threshold=0.70)
       │                                        │
       ▼                                        │
【Step 4: 最終回答生成 (IntegrationEngine v2.0)】 │
       ├─ Tension有: 視点対立配慮型プロンプト      │
       └─ Tension無: 通常統合型プロンプト         │
       │                                        │
       └──────────────────┬─────────────────────┘
                          │
                          ▼
【Step 5: 応答キューブ化 (a_cube) & 相互因果リンク & 時間進め】
       │
       ▼
【(Option Step 6): 記憶代謝サイクル (Defrag & GC)】
```

---

## 📝 各ステップのミリ単位詳細シーケンス

### 【Step 1: ユーザー入力の受付と「問い」のキューブ化】
1. **グローバルターンの更新**:
   `hub.tick()` を実行し、システムの時間を1進める (`global_turn += 1`)。
2. **問いキューブ（q_cube）の錬成**:
   `q_cube = cube_eng.make_cube(query=user_query, role="history", source="USER", current_turn=hub.global_turn)`
   * LLMにより6種類のキーワード（`genre`, `topic`, `problem/theme`, `subject`, `predicate`, `key_phrase`）を抽出。
   * Embedding APIを叩き、`DynamicProjector` により `int3_grid` (8階調), `int8_grid` (256階調), `grid_mesh` (10,000階調) を一括付与。
3. **長期記憶への放り込み**:
   `hub.cube_add(q_cube)` で、全体記憶プール (`hub.cube_pool`) に保存。
4. **（注意点）**:
   プロンプト構築時の重複を避けるため、この時点ではまだ短期記憶（`active_history`）にはプッシュしない。

---

### 【Step 2: 思考の材料集め (SRAG v3.1 二段階探査)】
1. **SRAG探査の実行**:
   `search_results = srag_eng.search(q_cube, hub, mode="exploratory")` (または `"standard"`)
   * **近傍27グリッド抽出**: `q_mc.int3_grid` の周囲27マスから類似度 `≥ 0.75` の初期候補をピックアップ (`_select_starting_points`)。
   * **二段階メタ・セマンティクス計算**:
     * **前段階 (`half_score_1`)**: `genre`, `topic`, `problem/theme` の平均類似度（重み 60%）。
     * **後段階 (`half_score_2`)**: `subject`, `predicate`, `key_phrase` の平均類似度（重み 40%）。
   * **スコア算出**:
     $$\text{mini\_score} = (\text{half\_score\_1} \times 0.6) + (\text{half\_score\_2} \times 0.4)$$
     $$\text{final\_score} = (\text{mini\_score} \times 0.7) + (\text{context\_sim} \times 0.3)$$
   * **探索モード時 (`_run_exploratory_flow`)**: 10,000階調 `grid_mesh` 空間で DBSCAN (`eps=200`, `min_samples=2`) クラスタリングを行い、高密度クラスタの代表記憶を抽出。
2. **ワーク領域への格納**:
   SRAG検索結果 (`SearchResult` のリスト) を `hub.search_change_set(search_results)` で一時キャッシュ領域 (`srag_results`) にセット。

---

### 【Step 3: 葛藤の検知 (AnalyzeEngine v9.3)】
1. **実行条件分岐**:
   環境変数 `CONFLICT_DETECT_SWITCH == "True"` かつ `len(search_results) >= 2` の場合に起動。
2. **Tension検知処理**:
   `tension_meta = analyze_eng.detect_tension(search_results)`
   * **トピックロック**: ペア間の `MiniCube` 類似度 `> 0.75` で同一話題判定。
   * **張力測定**: 同一話題ペアの主 `embedding_vector` 類似度を測定。
   * **葛藤認定**: 最小類似度が **`tension_threshold = 0.70` 未満** の場合、`TensionResult(has_tension=True, tension_score=..., divergent_summaries=[...])` を生成。

---

### 【Step 4: 最終回答の生成 (IntegrationEngine v2.0)】

#### ➔ 【ルート 1: SRAG結果が0件の場合 (single)】
* `answer = integrate_eng.single(q_cube, hub.history_get_all())`
* **動作**: 直近対話履歴 (`active_history`) と `q_cube.summary` のみからプロンプトを構築し、`llm_service.call_api_generate(prompt)` で回答を得る。

#### ➔ 【ルート 2: SRAG結果が1件以上ある場合 (integration)】
* `answer = integrate_eng.integration(q_cube, search_results, hub.history_get_all(), tension_meta=tension_meta, conflict_detect_switch=True)`
* **動作**:
  * **Tension有 (`has_tension == True`)**:
    「⚡【意見の対立情報】」ヘッダーと対立サマリーをプロンプトに注入。**「意見を無理にまとめず、異なる視点を尊重して回答を作成せよ」** という指示を適用。
  * **Tension無 (`has_tension == False`)**:
    「【関連する過去の記憶】」として検索結果を注入し、調和の取れた回答文を作成。

---

### 【Step 5: システム応答の記録と「因果の紐付け」】
1. **Q-Cubeを短期記憶へ追加**:
   `hub.history_push(q_cube)`
2. **応答キューブ（a_cube）の錬成**:
   `a_cube = cube_eng.make_cube(query=answer, role="history", source="LLM", current_turn=hub.global_turn)`
3. **完全双方向の因果紐付け（相互リンク）**:
   * `a_cube.reactionLink_ID = q_cube.cube_id` （A-CubeからQ-Cubeを参照）
   * `q_cube.reactionLink_ID = a_cube.cube_id` （Q-CubeからA-Cubeを参照）
4. **長期記憶・短期記憶への格納**:
   * `hub.cube_add(a_cube)` で `cube_pool` に保存。
   * `hub.history_push(a_cube)` で `active_history` に保存。
5. **UI表示**:
   `ActivityMain` (コンソール) に `answer` を表示し、次の入力を待機。

---

### 【Option Step 6: チャット中の記憶代謝処理 (Defrag & GC)】
ユーザーが `'defrag'` と入力した際、または特定サイクルでバックグラウンド実行される。

1. **デフラグサイクル開始**:
   `defrag_eng = DefragEngine(hub, llm_service, cube_eng)`
   `defrag_eng.run_defrag_cycle()`
2. **衰退記憶（シード）の特定**:
   `c.defrag_target == True` かつ生命力 $\alpha < \text{defrag\_threshold} (0.75)$ の記憶を検出（`turn_guard = 5` 経過済みのもの）。
3. **DBSCAN前処理によるノイズ排除**:
   8階調 `int3_grid` 近傍マス内の候補に対し、10,000階調 `grid_mesh` で DBSCAN (`eps=500`, `min_samples=2`) をかけ、異物を除外した高密度クラスタを抽出。
4. **幾何学的重心 ➔ 疑似クエリ選出 ➔ 高次元精製**:
   重心に最も近い実存キューブを「疑似クエリ」に選定し、高次元ベクトル類似度でクラスタを100%精製。
5. **Origin（新概念）の生成 & 意味的品質検証**:
   LLMで抽象化した要約文から新 `Origin` キューブを生成。旧記憶と新Originの `MiniCube` ベクトル類似度（`≥ 0.75`）による **意味的保持率 `≥ 0.30` (30%)** で合格・採用。
6. **ガベージコレクション (GCEngine)**:
   `gc_eng = GCEngine(hub)` ➔ `gc_eng.run_gc_cycle()`
   要約された旧記憶の `is_archived` を `True` にセットし、`cube_pool` から `archived_cube_pool`（お墓）へ移動・隔離。
